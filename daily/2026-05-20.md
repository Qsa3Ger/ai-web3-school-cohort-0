# Day 2.5（超前学习）：智能合约（Smart Contract）

## 核心理念
智能合约不是"自动执行的法律合同"，而是**部署在链上的程序**。把规则、资产和状态放到公开可验证的执行环境里，也把错误、权限和升级风险暴露给所有人。

**类比：** 普通程序跑在你的电脑上，你信它就行；合约跑在所有节点上，人人可查，人人可调用。

## 为什么重要
Web3 产品的核心逻辑都在合约里：token、NFT、DEX、借贷、治理、质押、空投、账户抽象。
- 前端可以换，后端可以重构
- 但合约一旦部署，**修改成本和风险远高于普通代码**

学合约不是为了立刻写复杂协议，而是先建立判断力。

## 最小示例：Counter（计数器）

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
    uint256 public count;

    event CountChanged(uint256 newCount);

    function increment() external {
        count += 1;
        emit CountChanged(count);
    }
}
```

这个例子已经涵盖合约最核心的概念：
| 组件 | 说明 |
|------|------|
| `uint256 public count` | **状态变量** — 存在链上，公开可读 |
| `increment()` | **写操作** — 改变链上状态，需要 gas |
| `event CountChanged` | **事件** — 外部系统可索引的日志 |
| `external` | **可见性** — 允许外部调用 |

## 第一性原理
1. **合约的价值来自可验证执行，不来自"代码看起来很聪明"**
2. **状态公开可查** — 不是私有数据库，很多人会看到
3. **调用有成本和顺序** — 受 gas、区块顺序、外部状态影响
4. **权限必须显式** — 谁能 mint/pause/upgrade/withdraw 不能靠默认信任

## 知识节点

| 概念 | 一句话 | 难度 |
|------|--------|------|
| **Solidity** | EVM 最常见的合约语言 | 初级 |
| **EVM** | 智能合约的执行环境 | 中级 |
| **ABI** | 应用和合约沟通的接口说明书 | 初级 |
| **Event** | 合约留下的可索引日志 | 初级 |
| **Upgrade** | 合约升级 = 安全、治理、迭代的权衡 | 高级 |

## 完整调用流程（以"用户点击投票按钮"为例）

```
用户点击 → 前端编码 vote(proposalId)
  → 钱包展示交易 + 用户签名
  → 交易广播到 RPC 节点
  → 验证者打包进区块
  → EVM 执行 → 成功？更新状态 + emit event
  → 失败？revert
  → 前端监听回执 → 更新页面
  → 索引器读取 event → 更新历史记录
```

## 关键安全认知
- `view` 函数（读状态）不需要签名和 gas
- 写交易需要钱包签名 + 支付 gas
- **ABI 只告诉你"能调用什么"，不保证"调用是否安全"**
- Owner 权限太大时，用户实际是在信任管理员
- 没写事件 → 后续前端历史、索引、审计都会困难

## 常见错误
1. 把 view 函数和写交易混在一起
2. 没有处理 decimals（token 数量需要按 decimals 放大）
3. 只测成功路径，没测权限失败、余额不足、暂停状态
4. 把 owner 当成永远可信
5. 忽略事件设计

## 最小实践（阅读合约练习）
找一个已验证源码的简单 ERC-20 或 NFT 合约：
1. 在区块浏览器里查看源码、ABI、事件和最近交易
2. 找出哪些函数会改变状态，哪些只是读取
3. 找出权限函数：owner、admin、pause、mint、burn、upgrade
4. 找出最重要的 event，解释它对应用户的什么动作
5. 一句话：这个合约最重要的风险边界是什么
