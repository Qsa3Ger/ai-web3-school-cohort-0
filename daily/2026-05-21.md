# Day 3：最小实践 — 合约阅读 + Counter 部署

## 最小实践（合约阅读练习）

**合约：** Sepolia LINK Token
**地址：** `0x779877A7B0D9E8603169DdbD7836e478b4624789`

### 5 步练习

| 步骤 | 做了什么 | 结论 |
|------|---------|------|
| 1. 查看源码/ABI/交易 | 打开 Etherscan 四个标签页 | 已验证合约，Code / Read / Write / Events |
| 2. 区分读/写函数 | Read Contract（name, balanceOf...）vs Write Contract（transfer, approve...） | view 函数免费读；写函数要钱包签名+Gas |
| 3. 找权限函数 | 没找到！没有 owner/mint/pause/burn | 这是最纯粹的标准 ERC-20 |
| 4. 最重要的 event | Events 标签里全是 `Transfer` | 每次转账都记在链上日志里 |
| 5. 风险边界 | 规则固定、无人可控 | 安全：没人能作恶；风险：没人能救火 |

### 学到的新概念

- **Etherscan Read/Write Contract** 的界面区别
- **输入框 [0x...]** 是让你填地址参数，不是权限
- **无参数函数**（name, symbol, decimals）Etherscan 直接显示返回值
- **有参数函数**（balanceOf, allowance）需要填入地址再 Query
- `recipient` = `to`，参数名不重要，类型才重要

### 核心理解

> 合约把规则变成公共基础设施，也把 bug 变成公共风险。
> 普通程序：数据在本地，改了就改了。
> 智能合约：数据在链上，全球节点见证，写入就是永久的。

## Counter 合约部署

**合约地址：** `0x8d053498F37CFF640EF3F7b9dD710C4EC01CEA84`
**Etherscan：** https://sepolia.etherscan.io/address/0x8d053498F37CFF640EF3F7b9dD710C4EC01CEA84

### 源码

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
    uint256 public count;

    event CountChanged(uint256 newCount);

    function increment() external {
        count += 1;
        emit CountChanged(count);
    }
}
```

### 操作记录

| 操作 | 工具 | 结果 |
|------|------|------|
| 编译 | Remix Solidity Compiler (0.8.20) | ✅ 编译通过 |
| 部署 | Remix → Browser Extension → MetaMask (Sepolia) | ✅ 部署成功 |
| 读 count | Remix Deployed Contracts → count | `uint256: 0` |
| 调 increment() | Remix → increment → MetaMask 确认 → 上链 | ✅ 交易成功 |
| 再次读 count | Remix → count | `uint256: 1` ✅ |

### 关键理解

- Remix Environment 选 **Browser Extension**（新版本叫法）= 旧版的 Injected Provider
- 部署合约 **Value 必须设为 0 Wei**（部署本身不需要转 ETH）
- increment() 是**写操作**：需要 MetaMask 签名 + 付 Gas
- count 是链上状态：调用一次 +1，全球节点一致记录
